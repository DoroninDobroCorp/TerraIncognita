## 3. Что вылезло по ходу и стоит обдумать

- **Авторизация и многопользовательность.** Журнал, XP и офлайн — глобальное состояние экземпляра; сообщество доверяет `author_id` от клиента (карму и модерацию можно подделать). Минимальный план: подписанный токен устройства → зависимость `current_user` во всех роутерах → ключ `user_id` в каждом хранилище (миграция текущих данных в `"local"`) → модерация по уникальным аккаунтам с минимальным возрастом/кармой.
- **Офлайн-регионы честнее.** «Скачать регион» пока сохраняет только метаданные; sync-очередь отмечает записи синхронизированными, не применяя их.
- **Overpass — узкое место.** На холодном кэше запрос может занимать десятки секунд (теперь `/api/discover` отвечает по дедлайну, а медленный источник догружается в фоне). Свой зеркальный инстанс или предзагрев кэша по любимым районам снимет проблему.
- **Atlas Obscura режет серверный трафик** (HTTP 403) — сигнал «есть в Atlas» работает только если данные прошли; стоит поискать альтернативу или официальный доступ.
- **Достоверность посещений.** GPS/ID можно подделать — XP и туман «за факт присутствия» не верифицируются.

## 4. С чего продолжить

**Скорее всего, лучший следующий шаг** — решить, кто пользователь: только вы или другие люди. От этого зависит, нужны ли авторизация и SQLite раньше новых фич.

**Если «для себя»:**
- UI для эссе после прогулки (17) и «домой через 5 мест» (9)
- Heatmap «куда не ходил» (A1) + режим «заброшки рядом» (A5)
- Достижения с реальным смыслом (C15)

**Если «для всех»:** авторизация → SQLite → верификация посещений → модерация по аккаунтам.
